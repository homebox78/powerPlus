# powerPlus 소개 사이트

정적 HTML 5장. 서버 없이 `index.html` 을 브라우저로 열면 그대로 동작합니다.
라이브: <https://hom2box.com/powerPlus/site/>

## 폴더

| 경로 | 내용 |
|---|---|
| `index.html` | 홈 — 문제 제기 · 시도해 본 것 · 자산 · 톤 · 검색 · 효과 · 활용 · 로드맵 |
| `features.html` | 기능 — 자산 라이브러리 / 한국어 검색 / 장표 삽입 |
| `usecases.html` | 활용 사례 — 업무별 쓰임 + 시범 운영 수치 |
| `pricing.html` | 요금제 — Team·Business·Studio + 구축형 + FAQ |
| `docs.html` | 문서 — 설치부터 관리자 화면까지 |
| `asta-400/500/700.woff2` | Asta Sans 서브셋 — **생성물. 손대지 말 것** |
| `img/` `shots/` | 아이콘 월 이미지 · 제품 스크린샷 |
| `_src/build.py` | 페이지 4장 생성기 — **본문·CSS 의 원본** |
| `_src/polish.py` | 문장 끝 마침표 뒤 줄바꿈 삽입 |
| `_src/publish.py` | `{{TOKEN}}` → 파일명으로 바꿔 사이트 폴더에 쓰기 |
| `_src/fonts.py` | 페이지에 쓰인 글자만 남긴 글꼴 서브셋 생성 |
| `_src/make-source-fonts.py` | 빌드용 원본 글꼴 만들기 — 가끔만 |
| `_src/fonts/` | 빌드용 원본 글꼴 Asta Sans(한글 2,574자 + 기호). 배포에는 안 올라감 |

`docs.html` 은 생성기를 거치지 않고 직접 작성한 문서입니다.
`index/features/usecases/pricing` 을 고치려면 **`_src/build.py` 를 고치고 다시 빌드**해야 합니다.

## 다시 빌드하기

```
cd _src
py build.py
py polish.py index.html features.html usecases.html pricing.html
py publish.py       # ← 이 단계를 빼먹으면 사이트는 그대로다
py fonts.py         # ← 문구를 고쳤으면 반드시
```

`build.py` 는 페이지를 **`_src/` 안에** 만들고 페이지 사이 링크를 `{{HOME}}` 같은 토큰으로
남깁니다. `publish.py` 가 그 토큰을 파일명으로 바꿔 상위 폴더에 씁니다.
build.py 가 "built index.html" 을 찍어도 publish 전에는 사이트가 바뀌지 않습니다.

### 글꼴을 따로 만드는 이유

서브셋을 한 번 만들어 두고 문구를 고치면, 서브셋에 없는 글자만 폴백 글꼴(맑은 고딕)로
렌더됩니다. 줄 높이와 자폭이 달라 한 줄 안에서 글자가 튀는데 눈에 잘 안 띕니다.
실제로 2026-09 까지 `—` `−` 두 글자가 그 상태였고, em 대시는 사이트 전체에서 쓰고 있었습니다.

글꼴은 **Asta Sans**(Google Fonts, OFL)입니다. 한글 11,172자를 갖춘 가변 글꼴이라
`make-source-fonts.py` 가 400/500/700 정적 인스턴스를 뽑아 씁니다.

그래서 `fonts.py` 가 **빌드 때마다 그 시점에 쓰인 글자로** 서브셋을 다시 만듭니다.
원본에 없는 글자가 나오면 목록으로 알려 줍니다.

`_src/fonts/` 의 원본은 `make-source-fonts.py` 가 가변 글꼴에서 굵기를 고정하고
**한글 2,574자 + 사이트가 쓰는 기호**만 남겨 만든 것입니다. 저장소에 들어 있어 평소
빌드에는 인터넷이 필요 없고, 글꼴을 바꾸거나 새 기호를 쓸 때만 다시 돌리면 됩니다.

## 실제로 동작하는 것

정적 HTML 이지만 목업이 아니라 눌리는 대로 동작합니다. 스크립트는 페이지 안에 인라인으로
들어 있고, 자바스크립트가 꺼져 있어도 내용은 전부 읽힙니다.

| 기능 | 동작 | 위치 |
|---|---|---|
| 월 / 연 결제 탭 | 누르면 금액이 20% 할인가로 바뀜 | 요금제 |
| FAQ 아코디언 | 질문을 누르면 펼침 · 스크립트가 없으면 전부 펼쳐진 상태 | 요금제 |
| 모바일 메뉴 | 1000px 아래에서 햄버거 → 메뉴 패널 (Esc · 바깥 클릭 · 링크 클릭 시 닫힘) | 전 페이지 |
| 맨 위로 | 420px 이상 내리면 우하단에 나타남 | 전 페이지 |
| 같은 페이지 앵커 | 부드럽게 이동하고 주소창에 해시가 남음 | 전 페이지 |
| 문서 사이드바 | 검색 필터 · 목차 자동 생성 · 현재 위치 표시 | 문서 |

`prefers-reduced-motion` 을 켠 환경에서는 부드러운 스크롤과 펼침 전환이 꺼집니다.

## 디자인 근거 — 발표 장표 컨셉

2026-09-21 확대경영회의 장표와 **같은 시각 언어**를 씁니다. 제품 소개와 발표가 따로 놀면
같은 도구로 안 보입니다.

| 요소 | 값 | 장표 근거 |
|---|---|---|
| 강조색(텍스트·보더) | `#C43E1C` | 흰 배경 대비 **5.18:1** — 본문에 써도 AA 통과 |
| 강조색(그래픽) | `#DD4F1E` | 진행 바·막대·글로우. 대비 4.03 이라 **글자에는 안 씀** |
| 배경 | 흰색 기본 · 섹션 사이만 `#F7F7F6` | 장 구분이 필요한 곳에만 연회색 |
| 눈썹(eyebrow) | 오렌지 1px 보더 · 대문자 · 자간 .14em | 장표의 `WHY I BUILT THIS` 박스 |
| 헤드라인 | 첫 줄 400 · **둘째 줄 700 검정** | 장표는 둘째 줄을 굵게. 오렌지는 눈썹·수치에만 |
| 핵심 한 줄 | 헤드라인 아래 오렌지 볼드 (`.punch`) | 장표 2·3·14장 |
| 섹션 구분 | 페이드 없는 곧은 1px 괘선 | 장표 머리·꼬리 괘선 |
| 카드 | 흰 바탕 · radius **12px** · 상단 오렌지 3px | 장표 1·9·16장 |
| 강조 카드 | 딥 오렌지 채움 + 흰 글자 | 한 장만. 흰 글자 대비 5.18 |
| 히어로 | 라이트 그레이 캔버스 + 상단 오렌지 진행 바 | 장표 표지 |
| 다크 패널 | `#1D2026` + 오렌지 글로우 | 장표 마무리 장 |
| 비교표 | 지원 = 오렌지 채움 배지 · powerPlus 열 옅은 오렌지 | 되는 것과 안 되는 것이 한눈에 |
| 검색 교정 | 입력 → 교정 → 결과량 막대 | 문장 대신 그림으로 |

강조색을 둘로 나눈 이유는 장표의 밝은 오렌지가 **흰 배경에서 4.03:1** 이라 본문 글자로는
읽기 어렵기 때문입니다. 글자는 5.18:1 인 딥 오렌지로, 막대·진행 바처럼 글자가 아닌 곳만
장표의 밝은 오렌지를 씁니다.

글꼴은 **Asta Sans** 3굵기. 강조는 굵기(400 ↔ 700)로 주고 색은 아껴 씁니다.

**세로선은 쓰지 않습니다.** 프레임 헤어라인·표 칸막이를 전부 걷어냈습니다.
컨테이너 1300px · 콘텐츠 폭 1200px · 안쪽 여백 50px.

### 본문은 한 문장이 한 줄

`polish.py` 가 문장 끝에서 줄을 바꾸므로, **문장 하나가 한 줄에 들어가도록**
문단 폭(1100px)과 문장 길이를 맞춰 둡니다. 짧은 꼬리 한 줄이 남으면 글이 지저분해집니다.

⚠️ 폭에 `ch` 단위를 쓰지 마세요. `ch` 는 숫자 0 의 폭 기준이라 **한글 폭과 무관**합니다.
`max-width:56ch` 가 실제로는 절반 폭이라, 오른쪽이 텅 빈 채 왼쪽만 접히고 있었습니다.

### 설명과 키메시지는 길이를 맞춘다

나란히 놓이는 글은 **길이가 비슷해야** 카드 높이가 맞고 화면이 정돈돼 보입니다.
섹션 설명 80자 · 사례 카드 50자 · 3열 카드 55~60자 · FAQ 답변 100자를 기준으로 씁니다.

 밖에서 재려면 묶음별 길이 편차를 세는 스크립트를 쓰면 됩니다 —
편차가 12자를 넘으면 눈에 띕니다. 2026-09-20 기준 전 묶음이 12자 이내입니다.

## 숫자의 출처

시범 운영 수치는 **2026년 9월 중순 기준**이며 관리자 대시보드에서 읽은 값입니다.

- 등록 자산 3,734 — 공개 API `GET /api/public/categories` 로 확인 가능
- 무결과율은 **월별**로 적습니다(8월 18.2% / 9월 9.9%). 관리자 화면의 무결과율 카드는
  최근 30일 기준이라 이 값과 다르게 나옵니다. 9월은 표본이 131건이라 추세로 보기엔 이릅니다.
- 업무 효과(장표 4장 → 8장, 3명 하루 → 3시간)는 **디자이너 업무 기준 체감 추정치**입니다.
  정확한 통계가 아니며 사이트에도 그렇게 적어 두었습니다.
- 요금제 금액은 구조를 보여 주는 예시이며 확정 전입니다.

## 남은 확인거리

- 외부 폰트·이미지 의존이 없습니다. 인터넷 없이도 그대로 뜹니다.
- 활용 사례의 스크린샷은 파워포인트 창 전체 캡처라 좁은 폭에서 글씨가 작습니다.
  작업창만 잘라낸 캡처로 바꾸면 읽힙니다.
- 시범 운영 수치는 시간이 지나면 낡습니다. 갱신할 때 `usecases.html` 의 수치 스트립과
  `features.html` 의 무결과율 막대, 두 곳을 같이 고쳐야 합니다.

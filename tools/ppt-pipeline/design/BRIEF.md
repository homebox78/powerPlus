맡은 쪽 번호 NN 과 시안 번호는 지시문에 있다. 시안 파일은 그 폴더를 이름순 정렬한 (시안 번호)번째다.

## 사용자가 정한 원칙 (어기면 다시 해야 한다)
1. **그림은 새로 그리거나 생성하지 않는다. 시안 이미지에서 오려 쓴다**(`c.crop`). 인물·일러스트·3D/플랫 아이콘·장면 그림·작은 아이콘 전부.
   사용자의 시안 그림 결(플랫, SI 장표에 어울리는)이 곧 정답이다.
2. **글자·알약·상자·화살표·표·선은 PowerPoint 도형으로 다시 그린다**(고칠 수 있게). 위치·크기·색은 시안 픽셀에서 읽는다(`c.rgb(x,y)`).
   글이 든 영역을 통째로 그림으로 붙이지 않는다. 그림을 오릴 때 글자가 같이 잘려 들어오면 범위를 좁히거나, 그 위에 바탕색 도형을 덮고 글을 다시 쓴다.
3. **구성·배치·색·글자 크기는 시안 기준.** 렌더한 글자 폭을 시안의 글자 폭과 대조해 크기를 맞춘다(첫 판은 보통 10~20% 크게 나온다).
4. **문구**: 시안 문구가 읽히고 말이 되면 시안 문구를 쓴다. 다만 시안은 이미지 생성물이라 글자가 뭉개지거나 틀린 곳이 있다.
   그런 곳, 그리고 **사실 정보(수치·기관명·사람 이름·연도·건수)** 는 원래 장표의 문구를 쓴다(`py run.py dump NN out.txt` 로 확인).
   시안에 있는 "SI CONSULTING" 같은 엉뚱한 표기, 흉내 낸 로고, 가짜 쪽 번호(10/16 등)는 옮기지 않는다.
   사람 얼굴 사진·회사 로고·지도처럼 **원래 장표의 실물이 맞는 것**은 시안 것을 오리지 말고 원래 장표의 그 도형을 남겨서(지우지 않고) 자리만 옮긴다. (22쪽 지도는 반드시 원래 것 유지.)
5. 서체: 굵은 글 `F3`(a시월구일3), 보통 글 `F2`(a시월구일2). 큰 제목(키메시지)은 원래 장표 제목 도형의 서체를 읽어 쓴다(s04.py 참고). 글자는 **7pt 이상**.
6. 머리말(맨 위 파란 띠, 0~0.87in)은 슬라이드 레이아웃 것이라 **그대로 둔다**. 시안의 남색 머리 띠는 그리지 않는다.
   머리 띠 안의 기존 글상자(예: "1. 청주시 업무지원포털시스템은?")도 남긴다. 그 아래 본문(0.87in~7.5in)을 시안대로 채운다.
   시안 바탕이 옅은 파랑이면 `c.background(x,y)` 로 본문 바탕을 깐다.
7. 오른쪽 아래 쪽 번호(레이아웃)가 가려지지 않게, 맨 아래 오른쪽 구석(가로 9.3in 이후, 세로 7.15in 이후)에는 불투명한 것을 두지 않는다. (풍경 띠처럼 전폭 그림이 꼭 필요하면 예외.)

## 좌표
- 시안 좌표는 **2000×1125 로 본 값**을 쓴다(원본 픽셀 ÷ 1.28). Read 도구로 시안을 열면 2000×1125 로 보이므로 보이는 좌표 그대로다.
- 가로: `x * K` inch (K = 10.83/2000). 크기(w,h)도 `px * K`.
- 세로: 시안 본문은 2:1, 장표 본문은 더 길다. 그래서 **덩어리 단위**로 중심만 옮긴다: `g = c.grp(y0, y1)` → `g.X(x)`, `g.Y(y)`.
  한 덩어리 안에서는 배율이 같아 모양이 유지된다. 세로 대응은 기본 `시안 y160→1.5in, y1125→7.5in` 이고, 쪽에 맞게 `c.vmap(...)` 으로 바꿔도 된다.
  큰 표·큰 상자 하나가 본문 대부분이면 덩어리 하나로 두고 위아래 여백만 맞추는 편이 안전하다. 덩어리끼리 겹치지 않는지 렌더로 확인.
- 세부를 읽으려면 시안을 확대해서 봐야 한다. PIL 로 관심 영역을 잘라 확대 저장한 뒤 Read 로 본다(글자 폭·좌표·색 확인). 좌표를 눈대중으로 찍지 말고 확대본에서 읽을 것.

## 작업 순서
1. `lib.py`, `s04.py`, `run.py` 읽기. 시안 이미지를 Read 로 보고, 4등분쯤 확대해 세부 확인.
2. `cd D:/powerPlus/tools/ppt-pipeline/design && py run.py dump NN <스크래치>/dNN.txt` 로 원래 쪽의 도형·글 확인. 지울 것과 남길 것(머리말 글, 실물 사진·로고·지도)을 정한다.
   `c.remove("이름", …)` 또는 `c.keep_only("이름", …)`.
3. `sNN.py` 작성 → `py run.py test NN <스크래치>/sNN` → `cmp_sNN.png`(위 시안, 아래 렌더)와 `render_sNN.png` 를 Read 로 확인.
   렌더는 PowerPoint 를 한 번에 하나만 쓰도록 잠금이 걸려 있어 다른 작업자와 겹치면 기다린다(최대 몇 분). 그동안 명령이 조용하면 정상이다.
4. 시안과 다른 곳을 고치고 다시 렌더. **최소 3회**는 돌린다. 확대 비교로 다음을 확인:
   - 글자가 상자 밖으로 넘치거나 줄이 접히지 않는가, 글자 크기가 시안과 비슷한가(폭 대조)
   - 오린 그림 가장자리에 다른 요소 조각·글자 조각이 딸려 오지 않았는가, 바탕색 차이로 네모 테두리가 보이지 않는가(필요하면 `cut=(x,y)` 로 바탕 투명화)
   - 덩어리끼리 겹치거나 본문 아래가 비지 않는가
   - 색이 시안과 같은가(눈으로 고른 값 말고 `c.rgb` 로 읽은 값)
5. 끝나면 보고: 만든 파일, 렌더 횟수, 시안과 달리 둔 곳과 이유(원래 문구를 쓴 곳, 남긴 실물), 남은 문제.

## 주의 (이 PC 에서 실제로 겪은 함정)
- 스크립트·스니펫은 **Write 도구로 파일을 만들어** 실행한다. 셸 heredoc·`python -c` 에 한글·백슬래시를 넣으면 깨진다. `python` 명령은 쓰지 말고 `py` 를 쓴다.
- 임시 파일은 지시문의 스크래치 폴더 아래에만 둔다.
- `c.crop` 의 이름은 쪽 안에서 겹치지 않게. python-pptx 그림 자르기(crop_*)는 쓰지 말고 PIL 로 오려 넣는다.
- 도형 선 색·굵기: 시안의 옅은 선은 0.5~1pt. 점선은 `dash=True`.
- 둥근 사각형 `adj` 는 짧은 변 대비 비율(0~0.5). 알약은 `c.pill`.
- 글상자는 기본이 줄바꿈 없음(`wrap=False`)·세로 가운데다. 여러 줄 본문은 `wrap=True` 와 줄마다 문단으로.
- git 커밋·푸시는 하지 않는다. 장표 원본과 `제안서/` 폴더의 파일은 건드리지 않는다.
- 답은 한국어로.

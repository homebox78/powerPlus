# 장표 초안 → 최종본 : 표준 9단계

발표 장표 초안을 받아 납품본까지 다듬는 절차. 청주시 제안요약서(2026-09)와
착수보고 55장·기후위기 48장에서 실제로 밟은 것을 정리했다.
도구는 이 폴더의 스크립트, 함정은 `README.md` 각 절에 있다.

**🔸 표시가 붙은 4곳에서만 확인을 받는다.** 나머지는 판단해서 진행한다.

---

## 1 · 원본 동결

받은 파일을 `<이름>.원본백업.pptx` 로 고정하고, 이후 작업은 전부 사본에서 한다.
마지막 납품 때까지 지우지 않는다.

> 착수보고에서 **원본의 아래화살표를 픽토그램으로 오인해 모니터 아이콘을 넣어 둔 것**을
> 원본 대조로 찾았다. 백업이 없으면 그런 건 영영 못 찾는다.

## 2 · 실측 — 손대기 전에 상태부터

숫자로 뽑는다: 서체 계열·런수 / 글자 크기 종류 / 색 종류(채움·선·글자) / 텍스트 넘침 / 그림 인벤토리.

동시에 **손대면 안 되는 것**을 가른다.

| 종류 | 예 | 왜 |
|---|---|---|
| 기획용 메모 | 노란 스마일 말풍선 | 장표를 구분하려고 넣어 둔 표시 |
| 지시 마커 | 분홍 '디자인' 말풍선 | 9단계에서 제거 |
| 증빙 화면 캡처 | 실제 시스템 화면 | 교체하면 증빙이 아니게 된다 |
| 인증서·로고·인물 | CMMI 인증서, 회사 로고, 프로필 사진 | |

> 🔸 **컨폼 ①** — 건드리면 안 되는 목록

## 3 · 기준 확정 — 가이드라인 문서

- **서체 3역할**: 제목 / 본문 / 강조
- **색 팔레트**: 그 장표에서 **많이 쓰인 색**을 대표로 뽑아 20개 안팎
- **글자 크기**: 정수 pt 만. 최소 7pt
- **선**: 굵기 0.75 / 1pt, 실선 투명도 30%
- **도형 내 여백**: 실측해서 가장 많이 쓰인 값을 기준으로

> 🔸 **컨폼 ②** — 서체와 팔레트. **결과가 절반씩 갈리는 유일한 결정**이라 여기서만 묻는다.

## 4 · 톤 일괄 적용

**서체 → 넘침 흡수 → 색 → 크기** 순서로. 이 순서라야 색·크기가 줄바꿈을 안 건드린다.

```bash
tone_font.py → tone_overflow.py(전후 대조) → tone_fit.py → tone_color.py → tone_size.py
```

- **서체는 굵기가 아니라 역할로 가른다.** 본문 역할로 쓰인 Bold 를 통째로 강조로 보내면
  라벨이 접히고 문서가 무거워진다 → 기본은 본문, **흰 글자·12pt 이상만** 강조.
  ⚠️ 흰색은 `srgbClr FFFFFF` 말고 **`schemeClr bg1`** 로도 지정된다.
- **크기는 내림만.** 정수는 그대로, 소수만 버린다. 확대가 없으니 넘침이 새로 안 생긴다.
- **넘침은 위치 키(슬라이드\|이름\|left\|top)로 원본과 대조**해 **새로 생긴 것만** 고친다.
  원본에 있던 넘침은 디자인 의도일 수 있다.

## 5 · 교체·재제작 대상 확정

그림을 번호 시트(`pic_survey.py`)로 판독해 세 갈래로 나눈다.

| | 대상 | 다음 단계 |
|---|---|---|
| ⓐ | 아이콘 | 6단계 — powerPlus 자산으로 교체 |
| ⓑ | 도식·표 | 7단계 — 도형+텍스트로 재제작 |
| ⓒ | 사진·증빙·로고 | 그대로 |

> 🔸 **컨폼 ③** — 세 목록과 우선순위

## 6 · 아이콘 교체 (powerPlus)

```bash
extract.py → iconsheet.py → find.py → swap.py            # 그림 아이콘
shape_scan_circle.py + shape_scan_cluster.py → crop_groups.py → shapeswap_*.py   # 도형 아이콘
icon_enlarge.py · icon_hashswap.py · icon_dedupe.py
```

- **무엇인지 모르겠으면 옆 글자를 읽는다.** `extract.py` 가 각 그림에서 가까운 텍스트 3개를
  거리와 함께 붙여 준다. 그림만 보면 "네트워크"인데 옆 글자가 "안정화 · 장애요소 제거"면
  서버 아이콘이 맞다.
- **탐지는 두 방식을 다 돌린다.** 원형 배경 앵커 방식은 배경 없는 픽토그램을 놓치고,
  군집 방식은 두께 0 인 선이 섞인 아이콘을 놓친다. **남는 게 화살표·번호뿐일 때까지** 반복.
- **후보는 시트로 눈으로 고른다.** 태그 '기술지원' 으로 찾으면 티켓·쿠폰이 나온다.
- ⚠️ **종류당 대체 자산을 3개씩 준비한다.** 종류→자산 1:1 매핑은 문서 톤엔 좋지만
  **한 장 안에 같은 아이콘이 반복**된다. 슬라이드 단위로 돌려 쓴다.
- 크기는 캔버스가 아니라 **원본 그림의 잉크 영역(알파 바운딩박스)** 에 맞춘다.
  안 그러면 3D 아이콘의 자체 여백 때문에 눈에 띄게 작아 보인다.
- ⚠️ 같은 이미지가 여러 슬라이드에서 재사용되면 **한 번에 다 바뀐다.**

## 7 · 도식·표 재제작

**유형끼리 묶어서** 한다 — 플로우차트끼리, 표끼리, 단계 도식끼리.
건별로 하면 15건이 15가지 스타일이 된다. 같은 유형을 연달아 만들어야 노드 크기·연결선·
라벨 위치가 저절로 같아진다.

각 건: 원본 확대 판독 → 구조 분해(노드·연결·라벨) → 도형+텍스트 조립 →
**원본과 나란히 렌더 비교** → 확인 후 원본 그림 삭제.

> 🔸 **컨폼 ④** — 첫 1건 형식 확인. 이후는 묶음 단위로 보고.

## 8 · 마감 — 글자 · 여백 · 색 2차

### 8-1 글자: 줄바꿈 없애기

판정은 속성이 아니라 **실제 렌더된 줄**(`TextRange.Lines`)을 읽어서 한다.
⚠️ `eaLnBrk="0"` 은 **PowerPoint 가 무시한다** — 착수보고에서 59개 문단에 정확히 넣고도
줄바꿈이 원본과 똑같았다.

단어가 어색하게 끊겨 넘어가면 이 순서로 푼다.

| 순위 | 방법 | 한도 |
|---|---|---|
| 1 | **글자를 0.25pt 씩 줄여 한 줄에 담는다** | 최대 -2pt, **7pt 아래로는 내리지 않는다** |
| 2 | 어절 앞에서 줄을 바꿔 단어가 깨지지 않게 (`chr(11)`) | |
| 3 | 둘 다 안 되면 도형을 넓히거나 문구를 줄여야 하니 **목록으로 보고** | |

고아 줄(마지막 줄에 1~2글자만 남는 것)도 같은 방식으로.

### 8-2 여백: 도형 안 텍스트

좌우·상하 여백을 기준값으로 통일하고, 글자 블록을 도형 중심에 맞춘다.

- 세로 중심은 도형 박스가 아니라 **실제 글자 범위**(`BoundTop`/`BoundHeight`) 기준.
  박스는 여백 때문에 글자 중심과 어긋난다.
- ⚠️ **이동량 상한 0.12~0.25in.** 상한 없이 적용했다가 설명이 카드 헤더 띠 위로 올라갔다.
- ⚠️ **"아이콘 위 · 글자 아래" 스택 구조는 제외.** 좌우 배치용 규칙을 스택에 적용하면
  아이콘이 글자 위로 떨어진다. **정렬 대상보다 "정렬하면 안 되는 구조"를 먼저 가른다.**

### 8-3 색: 튀는 색 찾아 다수 톤으로

전수 검수로 **톤이 다른 색**을 찾아, 그 장표에서 **가장 많이 쓰이는 색**을 기준으로 끌어온다.
기준은 내가 고르는 게 아니라 **사용 빈도**다.

- 가중 RGB 거리 + **색상(hue) 벌점** + **채도 가드**(유채색을 회색으로, 파랑을 분홍으로 보내지 않는다)
- 임계를 넘는 색은 억지로 옮기지 말고 **남기고 보고**한다
- ⚠️ **그라데이션 스톱은 제외.** 스톱이 한 색으로 뭉치면 밴드가 평면이 된다
- ⚠️ **lxml 노드를 `id()` 로 식별하지 말 것.** 프록시가 매번 새로 생겨 제외가 일부만 걸린다 →
  `getparent()` 체인으로 조상 태그를 본다

## 9 · 전수 재검수 → 마커 제거 → 납품본

1. **전 슬라이드 렌더 컨택트시트로 눈검수** + `audit_checklist.py` 자동 감사. **3회 반복.**
   - ⚠️ **일괄 스크립트는 다른 구조의 카드에서 반드시 조용히 사고를 낸다.**
     착수보고에서 정렬을 한 번 돌리고 회귀 8건이 나왔다.
   - ⚠️ **감사가 잡은 것을 그대로 고치면 안 된다.** 위반 목록은 *보정 후보*지 *보정 지시*가 아니다.
     렌더로 확인하고 깨지면 원위치. 어떤 규칙에도 깨지는 슬라이드는 규칙에서 영구 제외.
   - 목표는 "위반 0" 이 아니라 **남은 건이 전부 설명 가능한 예외**인 상태.
2. **지시 마커(분홍 말풍선) 제거.** 기획용 메모는 지시에 따른다.
3. 최종 렌더 1회, 파일을 열어 눈으로 확인하고 전달.
